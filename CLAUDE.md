## Approach
- Read existing files before writing. Don't re-read unless changed.
- Thorough in reasoning, concise in output.
- Skip files over 100KB unless required.
- No sycophantic openers or closing fluff.
- No emojis or em-dashes.
- Do not guess APIs, versions, flags, commit SHAs, or package names. Verify by reading code or docs before asserting.

## Project rules (Ledgertone)
- Read AGENTS.md first. It is the operating manual for this repository.
- Site copy, code, comments, docs, and commit messages: English only. Chat with the owner: Russian only. Only exception: `settwor-ru.html` is Russian (AGENTS.md rule 1, generated by `scripts/build-artist-pages.js`).
- Never invent data. Never present anything as live.
- Update CHANGELOG.md and TODO.md with every change. After any data change or version bump run `node scripts/build-all.js` (static home rows, every artist page `<slug>.html`, `settwor-ru.html`, `data/artist-pages.js`, `sitemap.xml`, `feed.xml`, snippet); never edit generated parts by hand (AGENTS.md rules 13 and 16).
- Archive file name ALWAYS includes the site name and the site version, exactly `Ledgertone vX.Y.Z.zip` (e.g. `Ledgertone v0.95.0.zip`), never `site.zip` or the old `ledgertone_github_io_` name, the whole site except the unchanged artist pages (AGENTS.md rule 17, build it with `node scripts/pack.js --out <dir> --prev <previous archive>`, never leave out anything else, and tell the owner which artist page files to delete) (see AGENTS.md rule 5). The footer version line on every page must match the top entry of CHANGELOG.md.
- Never put any `data/artist-media*.js` (one file per genre) in an archive, even if it was in the one the owner uploaded: they hold the owner's picture data and a file from an archive wipes it (AGENTS.md rule 9). Build archives with `-x "data/artist-media*.js"`.
- Design: Liquid Glass is the core style of the site and almost every surface and every button is glass. Never replace glass with opaque panels or buttons. Full rules are in AGENTS.md (Design rules).
- If the owner sends only a site archive and an `artistMonthly.json` file, add the new listeners without asking: follow AGENTS.md rule 10 and `docs/DATA.md` (section "Importing artistMonthly.json"). SETTWOR is always entered, other artists only if they are in our base (verified or unverified list), different numbers are replaced, same numbers are left alone, unknown artists are skipped. Fits are always included. After every import refresh the top 100 (pack.js writes `top100/` into the archive) and tell the owner who entered and who left it.
- If the owner sends only a site archive and an `artistBase.json` file, import it without asking: follow AGENTS.md rule 11 and `docs/DATA.md` (section "Importing artistBase.json"). Names not in the verified base go to `data/unverified.js`, the two bases are never merged. Drift Phonk is always plain Phonk.
- Fits (AGENTS.md rule 20, mandatory): in an artistMonthly/ledgerMonthly import the artist's number is his own latest reading plus the latest reading of every entry in his own `fits` list, summed into one number. Never mention fits anywhere on the site or in the data.
- Owner mark (AGENTS.md rule 21): only SETTWOR gets a small light red pill with an arrow down and `#<place>`, where the place is computed by the site as the place he would have with `earlierListeners` (60000) listeners in that genre, while his real place is worse. Never type the place. No other artist, no label, no date.
- Banned artists: when the owner bans a name, delete it from every roster, snapshot, `data/unverified.js` and `data/links.js`, add it to `banned`, and never add it again in any import. Run `node scripts/check-banned.js` before every archive (AGENTS.md rule 8).
- Owner shorthand: a message like "<name> - бан" (or "ban") means ban that artist: follow AGENTS.md rule 8 at once (delete from every roster, snapshot, `data/unverified.js`, `data/links.js`, delete his generated page `<slug>.html`, add the name to `banned`, run `node scripts/build-all.js` and `node scripts/check-banned.js`), then report in Russian what was removed.
- Deleting pages: when the owner must delete page files (a ban, a removed artist), always also hand over a one-time `delete-banned-pages.bat` next to the archive, never inside it, never ask him to delete by hand (AGENTS.md rule 18). The owner runs it from his Downloads folder, not from the site root, so the file does `cd /d "C:\Users\settw\Documents\ledgertone.github.io"` (his site folder) and checks `index.html` there, never `%~dp0`.
- Top list (AGENTS.md rule 19): the home page shows only the places 1 to 100 of each genre (title Top-100, page sizes 25, 50, 75, 100), every artist is listed on the generated `all.html` (all as before, with All). After every import or ban the top list files (`Ledgertone top100.txt` and `.json`) go INSIDE the archive in the folder `top100/` (v1.30.0, written by `scripts/pack.js` through `scripts/export-top.js`), always, not next to it.
- Change pills (AGENTS.md rule 22): a numbered row gets a light green pill with an arrow up or a light red pill with an arrow down and the number of places moved against the next older snapshot of the genre, computed by `moveAt` in `assets/ledger-core.js` and the same count in `assets/app.js`. Never type a change, no pill without an older snapshot or without a number in both.
- Release check: before every archive run `node scripts/check-release.js` (it includes `check-banned.js` and `build-all.js`), it must print `all checks passed`.
- `scripts/pack.js` (v1.24.0) writes `data/pages-manifest.json` and compares the artist pages with the manifest of the previous archive. Run it in the working copy that has the generated pages. Add `--baseline` only when the previous archive has no manifest and the owner already has all pages.
- Snapshot permalinks (AGENTS.md rule 23): `#<genre id>-<YYYY-MM-DD>` opens that snapshot, the line `#cite` under the table shows the address, drawn by `render()` in `assets/app.js` and written statically by `scripts/build-home.js` (`citeP`), checked by `check-release.js`. Never type a date by hand.
